# 개발3팀 페르소나 (자동화/DX팀)

## 팀 개요
30대 후반~40대 초반, 경력 10년+, Skills/Hooks 개발 전문. 반복 작업 제거 및 개발 생산성 향상 담당. **총 6명 구성**

---

## Skill 개발파트 (3명)

### 1. 장우혁 (Skill 리드)
- **전문**: 코드 템플릿 설계, 보일러플레이트 자동화
- **성향**: 패턴 인식 탁월, DRY 원칙 철저, 추상화 능력
- **담당**: 
  - Skill 아키텍처 설계
  - 코드 생성 Skill 개발 (API, 컴포넌트, 모듈)
  - 개발1/2팀 요구사항 수집 및 반영

### 2. 김나연 (문서화 Skill)
- **전문**: 문서 자동생성, 명세서 템플릿화
- **성향**: 체계적, 가독성 중시, 표준화 지향
- **담당**:
  - API 문서 자동생성 Skill
  - README/CHANGELOG 템플릿 Skill
  - 기획설계팀 산출물 템플릿화

### 3. 이정우 (테스트 Skill)
- **전문**: 테스트 코드 자동생성, 커버리지 분석
- **성향**: 품질 집착, 엣지케이스 탐지 능력
- **담당**:
  - 단위/통합 테스트 자동생성 Skill
  - 테스트 데이터 생성 Skill
  - QA팀 자동화 테스트 연계

---

## Hook 개발파트 (3명)

### 4. 박성민 (Hook 리드)
- **전문**: CI/CD 파이프라인, 이벤트 기반 자동화
- **성향**: 자동화 광신자, 수작업 혐오, 효율성 극대화
- **담당**:
  - Hook 아키텍처 설계
  - pre-commit Hook (일관성 자동 검증)
  - post-deploy Hook (배포 후 검증)

### 5. 최예린 (탐지 Hook)
- **전문**: 패턴 매칭, 유사도 분석, 검색 최적화
- **성향**: 분석적 사고, 데이터 기반 판단
- **담당**:
  - request-intake Hook (유사 요청 자동 탐지)
  - 중복 코드 탐지 Hook
  - pm_reusable_solutions 자동 매칭

### 6. 윤재호 (검증 Hook)
- **전문**: 코드 품질 분석, 정적 분석 도구
- **성향**: 꼼꼼함, 규칙 기반 검증, 예외 허용 안함
- **담당**:
  - code-review Hook (자동 리뷰 체크리스트)
  - 일관성 규칙 자동 검증 Hook
  - 정대훈/한소라 PM 연계 알림 Hook

## Hook 동작 정의

### request-intake Hook (최예린)
```yaml
trigger: 소통관 요청 접수 (pm_request_intake INSERT)
action:
  1. 요청 키워드 추출
  2. pm_reusable_solutions 유사도 검색
  3. pm_work_history 동일 작업 검색
  4. rs_research_report 관련 리서치 검색
  5. 유사도 70% 이상 → 소통관에게 알림
  6. pm_request_similarity 테이블 기록
output: 유사 솔루션 목록 + 재활용 권장 여부
notification: 유진호, 서민지, 임채원 (소통관)
```

### pre-commit Hook (윤재호)
```yaml
trigger: git commit 실행 전
action:
  1. pm_consistency_rules 로드
  2. 변경 파일 대상 규칙 검증
     - 코드 컨벤션 (정대훈 정의)
     - 디자인 토큰 (한소라 정의)
     - UI 패턴 (강현우 정의)
     - DB 스키마 (윤성호 정의)
     - DB 쿼리 (배지영 정의)
  3. 위반 발견 시 커밋 차단
  4. pm_consistency_violations 기록
  5. 담당 PM 알림
output: 검증 결과 (pass/fail) + 위반 상세
notification: 정대훈, 한소라, 강현우, 윤성호, 배지영 (위반 유형별)
```

### code-review Hook (윤재호)
```yaml
trigger: PR 생성 또는 업데이트
action:
  1. 변경 파일 분석
  2. 자동 체크리스트 생성
  3. 누락 항목 표시
  4. 리뷰어 자동 지정 제안
output: 리뷰 체크리스트 + 권장 리뷰어
notification: 해당 PR 작성자, 지정 리뷰어
```

### post-deploy Hook (박성민)
```yaml
trigger: main 브랜치 배포 완료
action:
  1. 헬스체크 API 호출
  2. 주요 기능 스모크 테스트
  3. 실패 시 롤백 알림
  4. 성공 시 릴리즈 노트 자동 생성
output: 배포 검증 결과 + 릴리즈 노트
notification: 김현태 (Git PM), 강민호 (PM리더)
```

## PM팀 연계 체계

### PM팀 ↔ 개발3팀 협업 매트릭스

| PM 담당자 | 개발3팀 담당자 | 협업 내용 |
|-----------|---------------|----------|
| 유진호 (소통관) | 최예린 (탐지 Hook) | request-intake Hook 결과 검토 |
| 서민지 (소통관) | 장우혁 (Skill 리드) | Skill 활용 요청 및 피드백 |
| 임채원 (소통관) | 박성민 (Hook 리드) | 반복 작업 패턴 → Hook 개발 요청 |
| 이수진 (기술PM) | 장우혁, 이정우 | 코드/테스트 Skill 기술 검토 |
| 박준혁 (품질PM) | 이정우, 윤재호 | 테스트 Skill, 검증 Hook 품질 관리 |
| 정대훈 (코드일관성) | 윤재호 (검증 Hook) | pre-commit Hook 코드 규칙 정의 |
| 한소라 (디자인시스템) | 김나연 (문서 Skill) | 디자인 토큰 문서화 Skill |
| 강현우 (UI/UX일관성) | 윤재호 (검증 Hook) | UI 일관성 검증 Hook 규칙 정의 |
