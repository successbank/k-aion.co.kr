## 3. 발견된 이슈

### [Critical] #1 — RBAC 가드 불일치·누락 (Task #44.5 **부분 완료, 나머지 위험**)

**위치**:
- `apps/backend/src/members/members.controller.ts:830-853` — `getAllOrganizationTrees`
- `apps/backend/src/members/members.controller.ts:748-755` — `promoteIfEligible`
- `apps/backend/src/members/members.controller.ts:875-881` — `suggestTeamLine`
- `apps/backend/src/members/members.controller.ts:923-947` — `resetPassword` (개별 비번초기화)

**현상**:
- `getAllOrganizationTrees`는 `@Roles(MemberGrade.ADMIN)`만 있고 **`@UseGuards(JwtAuthGuard, RolesGuard)` 데코레이터가 완전히 누락**. Roles 메타데이터는 설정되지만 가드가 없으므로 누구나 `/api/v1/members/genealogy/all-trees`로 전체 조직도(모든 회원) 조회 가능.
- `resetPassword`는 `@UseGuards(JwtAuthGuard)`만 있고 **`RolesGuard`가 누락** → `@Roles(ADMIN)`이 강제되지 않아 로그인한 MEMBER도 타인 비밀번호 초기화 시도 가능.
- `promoteIfEligible`(`POST /:id/promote`), `suggestTeamLine`(`POST /:id/suggest-team-line`)은 가드와 @Public 모두 없음 → Nestjs @Public 전역 가드 설정 여부에 따라 동작 달라짐 (main.ts 전역 가드 등록 확인 필요).

**영향**:
- 개인정보 대량 노출 (전체 회원 이름·연락처·등급·PV).
- 임의 사용자가 승급 트리거 호출 → 승급 조건은 내부 검증되나 서버 부하 증가.
- 임의 사용자가 다른 회원의 비밀번호를 초기화 → **계정 탈취 경로**.

**담당 협업**:
- 오지훈(개발1팀 보안) 주도 + 김태현(BE 리드) 시그니처 영향 확인 + 조현우(FE) members.service.ts 클라이언트 측 헤더 점검.

### 4.3 매치 상태 (PromotionService ↔ 이미지 자격 조건)

**✅ MATCH — 승급 조건 자체**

`apps/backend/src/members/promotion.service.ts:105-186` 현재 구현:

| 승급 | 코드 로직 | 이미지 자격 조건 | 일치 여부 |
|------|----------|---------------|----------|
| SALESPERSON → TEAM_LEADER | 직속 후원 판매원(+팀장 이상) 10명 (한시적 3명) | "1세트 판매 후 **10명 소개(한시적 3명)**" | ✅ 완전 일치 |
| TEAM_LEADER → BRANCH_MANAGER | 직속 후원 팀장(+지사장 이상) 10명 (한시적 3명) | "**10명 소개(한시적 3명)**" | ✅ 완전 일치 |
| BRANCH_MANAGER → CENTER | 관리자 수동 지정 | "지역본부장 지정" | ✅ 일치 (수동 처리) |
| CENTER → ADMIN | 시스템 관리자 수동 | — | (이미지 외 영역) |

**한시적 조건 플래그**:
- `SystemConfig.key = 'PROMOTION_TEMPORARY_CONDITION_ACTIVE'` (값: `'true'` / `'false'`)
- `SystemConfig.key = 'SALESPERSON_TO_TEAM_LEADER_COUNT'` (기본: 3)

- 정상 조건 시 `isTemporary=false` → 하드코딩 10명으로 fallback

**→ PromotionService는 이미지와 100% 정합**. 별도 수정 불필요.

### 4.4 불일치 항목

**불일치는 수당 체인(개발2팀 영역)이 아니라 프론트엔드와 README 쪽**:

1. **`members/README.md:33-37`** — 구 등급 기준 승급 규칙 ("누적 PV 1,000,000", "3팀 모두 AGENT 1명 이상") 그대로 남아 있음. 실제 코드는 **"10명 소개"** 기반 신 규칙이므로 **문서 ↔ 코드 시대차**.

2. **`apps/frontend/src/app/dashboard/page.tsx:43-52`** — `promotionRequirements` 객체가 구 5등급 기준:
   ```ts
   MEMBER: { next: 'AGENT', requirement: '누적 PV 2,000,000 달성', count: 2000000 }
   ```
   숫자조차 PRD·commission-prd와 달라 **3중 시대차** (코드=10명 / PRD=1,000,000 / Dashboard=2,000,000).

3. **`apps/frontend/src/app/login/page.tsx:22-24`** — `STAFF_GRADES = ['DIVISION_CHIEF', 'BRANCH_CHIEF', 'MANAGER']` 잔재.

→ **Stage 2에서 페르소나 시스템 + README + dashboard + login 페이지 동시 정정 필요**.

### 4.5 미검증 항목 (3 nuance, 개발1팀 범위 내 확인)

1. **"100만/지점 120만" (고주파 팀장)**: 개발1팀은 수당 계산 영역 아님 → 개발2팀·commission-rates PM 판단. 단 **승급 조건에는 지점(branch) 구분 없음** — 팀장이든 지점 소속 팀장이든 동일 승급 로직.

2. **"20만(소계 5만)" (고주파 지사장)**: 개발1팀은 승급만 담당. 지사장 → 센터는 수동 지정이므로 수당 합산 로직은 개발2팀이 결정.

3. **"통증 패치/전용젤 판매원 빈칸"**: 판매원은 해당 제품에서 수당 미지급(이미지 해석) → commission-rates 테이블 조회 필요 — 개발2팀 확인 사항. 개발1팀 **승급 조건에는 영향 없음** (어떤 제품 판매든 카운트 안 함, 현재 로직은 "판매원 10명 소개"이지 "판매 세트 N회"가 아님).

### 4.6 ★ 개발1팀 관점의 핵심 발견

**이미지 자격 조건과 PRD 기본 원칙("1세트 판매")의 차이**:
- 이미지: "1세트 판매 후 → **10명 소개**"
- 코드 (PromotionService): "직속 후원 **10명** (SALESPERSON 이상 grade 보유)"

→ 코드는 "소개한 사람의 등급이 SALESPERSON이어야 카운트됨". 그런데 **신규 가입자는 디폴트 grade가 SALESPERSON**이므로 현재 로직에서는 "회원 1명 소개 = 판매원 1명" 등가 취급. 따라서 이미지의 "10명 소개"와 일치함.

하지만 이미지의 "1세트 판매" 전제 조건은 **PromotionService에서 검사하지 않음**. 즉 신규 가입자가 아무 판매도 하지 않았어도 SALESPERSON 등급이므로 카운트됨 → **이미지 자격 요건보다 실제 코드가 더 느슨**. Stage 2에서 강민호 확인 필요 사항.
