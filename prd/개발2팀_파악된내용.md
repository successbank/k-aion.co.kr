### 4.3 nuance 및 불일치 상세 분석

#### Nuance #1: 고주파 "100만 / 지점 120만"
- **가설**: 지점(BRANCH) 소속 팀장에게는 +20만 추가
- **현재 코드**: 단일 값 1,000,000. `ProductCommissionRate`에 `branchBonusAmount` 필드 없음
- **해결 옵션**:
  - A) 이미지에 오타 → 단일 100만 확정 → 현 코드 유지
  - B) 실제 비즈니스 규칙 → schema 확장 필요 (새 컬럼 or 조건부 rate row)
- **판단**: 강민호 결정 필요 (사용자 확인)

#### Nuance #2: 고주파 "20만 (소계 5만)"
- **가설 A**: 지사장 20만에 센터 몫 5만이 **포함**된 집계 (지사장이 실수령 15만)
- **가설 B**: 지사장 20만 + 별도 5만이 특정 조건 발생 (기본 15만 + 추가 5만)
- **가설 C**: 레이아웃 오독 (소계 5만은 센터의 합계 표시)
- **현재 코드**: BRANCH_MANAGER=200,000 (20만 전액)
- **해결 옵션**: 이미지 원본 재확인 + 강민호 결정

#### Nuance #3: 통증패치/전용젤 판매원 빈칸
- **현재 코드**: `SALESPERSON, 0` 명시적 row 존재 (**NULL이 아니라 0**)

- **이미지**: 330만
- **코드 seed**: 2,860,000 (286만)

### 5.2 규칙/패턴/제약

1. **이중 계보의 선택**:
   - 보너스(Calculator) → **sponsor 계보** (C1 fix 후 simulator도 sponsor)
   - 승급(Promotion) → **sponsor 계보** (주석 확정)
   - **recommender 계보는 현재 보너스에 사용되지 않음** (legacy code path)

2. **`teamLine` 1~3 CHECK 제약**: Kaion 고유 1:3 팀라인. 절대 해제/변경 금지 (schema.prisma:23 주석)

3. **ADMIN 제외 원칙**: 보너스 계산에서 `if (grade === ADMIN) continue`가 모든 Calculator/Simulator에 공통. ADMIN은 수당 대상 아님

4. **SALESPERSON 상위 라인 제외**: `if (ancestor.grade === SALESPERSON) continue` — 판매원 등급은 자기 직접 판매 수수료만 받고, 하위 판매로는 수수료 발생 안 함

5. **GRADE_ORDER 일관성**: `[ADMIN, CENTER, BRANCH_MANAGER, TEAM_LEADER, SALESPERSON]` — 낮은 인덱스 = 높은 등급. Calculator + Simulator + recognized-sales 모두 동일 순서 사용

6. **트랜잭션 원자성**: Sale 등록 → 재고 차감 → 보너스 계산 → PV 누적 → 승급 전체가 **한 `$transaction` 블록 안에서** 실행. 실패 시 전체 롤백 (sales.service.ts:150)

7. **주차 코드(weekCode) 포맷 분기 주의**:
   - sales.service.ts: `${year}-${ww}` (e.g., `2026-15`)
   - bonus-calculator.service.ts `getWeekCode`: `${year}-W${ww}` (e.g., `2026-W15`)
   - settlements.service.ts `generateWeekCode`: `${year}-W${ww}` (동일)
   - **★ 불일치 의심**: Sale.weekCode = `2026-15`, Bonus.weekCode = `2026-W15` → **JOIN 실패 가능**. Stage 4에서 검증 필요

8. **BonusType 매핑 규칙**:
   - SALESPERSON, TEAM_LEADER → `SALES_COMMISSION`
   - BRANCH_MANAGER, CENTER → `EDUCATION_MANAGEMENT`
   - ADMIN → 제외

9. **한시적 승급 조건 설정**: `SystemConfig` 테이블에서 관리. `PROMOTION_TEMPORARY_CONDITION_ACTIVE=true` 일 때 3명, `false` 일 때 10명. Stage 2 이후 관리자가 on/off 가능
