| 판매원/팀장 = 판매 수수료 | ⚠️ 부분 — `shared/constants.ts`의 `CommissionTypeTargetGrades[SALES_COMMISSION] = [SALESPERSON, TEAM_LEADER]`로 **백엔드/공유 패키지는 일치**, 프론트 UI는 미반영 |
| 지사장/센터 = 교육 관리 | ⚠️ 부분 — 동일 (shared 일치, 프론트 UI 미반영) |

### 불일치 항목

1. **UI 시대 차이**: compensation-plan / bonus-simulator / admin/organization 페이지가 **구 5등급 + 구 6종 보너스 명칭**(판매/판매관리/판권/판권관리/공유/센터운영) 하드코딩. 신 2종 체계(SALES_COMMISSION/EDUCATION_MANAGEMENT)와 신 4등급(판매원/팀장/지사장/센터)을 어느 페이지도 UI로 반영하지 않음.
2. **매트릭스 시각화 부재**: 이미지와 같은 제품 행 × 등급 열 표 구조가 프론트엔드에 **존재하지 않음**. 있는 것은 "보너스 타입별" 1차원 테이블 뿐.
3. **레거시 호환 맵**: `bonus-simulator/page.tsx` (line 43~72)와 `bonus-simulator.service.ts` (line 133~163)가 "신+구 등급 모두" 라벨/색상 매핑을 보유 → 과도기 데이터 수용하려는 의도는 있음. 그러나 UI 설명부는 여전히 구 체계만 노출.

### 미검증 nuance (이미지 vs 코드)

1. **"100만 / 지점 120만"** (온체 팀장 차등) — 프론트엔드는 5×4 매트릭스 UI 자체가 없어 "지점 120만" 표시 자리 없음. 백엔드 분석 후에야 UI 반영 여부 결정 가능. **현재 프론트엔드에 해당 표현 위치 없음.**
2. **"20만 (소계 5만)"** (온체 지사장) — 동일. 소계 표기용 UI 위치도 없음. `Statistic` 컴포넌트 `suffix`로 "(소계 5만)" 추가 가능성 있음.
3. **통증패치/전용젤 판매원 빈칸** — 현 UI는 매트릭스 테이블이 없으므로 "빈칸"을 렌더링할 공간 자체가 없음. 새 테이블 컴포넌트 도입 시 `render: (val) => val == null ? '—' : val` 패턴으로 처리 가능.

### admin/bonus-simulator UI에 매트릭스 시각화 가능 여부 평가 (Stage 2.1 관점)

**결론: 가능. 중간 난이도.**

**재사용 가능한 요소**:
- `CommissionRateCompareTab.tsx` 의 `Table` + `Collapse` 패턴 이미 존재 → 새 `ProductMatrixTab`을 같은 구조로 추가 가능
- `page.tsx` 가 이미 `Tabs`로 탭을 관리 (SaleSimulationTab / TeamConditionTab / CommissionRateCompareTab) — 4번째 탭 추가 트리비얼
- `bonusSimulatorService` 에 API 호출 패턴 있음 → 새 `getProductCommissionMatrix()` 메서드 추가 가능
- AntD `Table` 의 columns/dataSource 로 5제품 row × 4등급 column 구성 용이

**필요 작업**:
- 백엔드: `ProductCommissionRate` 전체를 제품×등급 매트릭스로 반환하는 GET API 추가 (`/api/v1/compensation-plan/product-matrix` 등)
- 프론트엔드: `ProductMatrixTab.tsx` 신규, columns=[제품명, 판매원, 팀장, 지사장, 센터, 판매가], dataSource=제품 5행
- 빈칸 처리: `render: (v) => v == null ? '—' : v.toLocaleString()`
- 각주 처리: "지점 120만", "소계 5만" 은 `Tooltip` 또는 각주 footer로

**난이도**: 중 (UI 자체는 반나절, 하지만 매트릭스 source 데이터 + nuance 3개 의미 결정이 선행되어야 함)

**권장**: Stage 2.1 에서 이 `ProductMatrixTab` 을 구현하면 **bonus-simulator UI 자체가 매트릭스 검증 도구로 직접 작동**하여 이미지 ↔ DB 정합을 즉시 시각 비교 가능.

## 5. 향후 개발 참조 사실

### 5.1 브랜드 컬러 진실값

- **실제 브랜드 컬러는 `#E53935` (Material Red 600)**, NOT `#7CB342`.
- `BRAND_COLORS` single source of truth: `/data/successbank/projects/kaion/packages/shared/src/constants.ts`
- primary `#E53935`, primaryLight `#EF5350`, primaryDark `#C62828`, success `#43A047`, error `#E53935`
- 어떤 디자인 작업이든 이 값을 기준으로 하고, 페르소나 카드의 `#7CB342`는 **Stage 2.5에서 수정 대상**

### 5.2 AntD + Tailwind 하이브리드 규칙

- `corePlugins.preflight: false` (tailwind.config.js) 필수 — 건드리면 AntD 스타일 깨짐
- `globals.css`는 Tailwind base/components/utilities + AntD override 혼재 — 수정 시 `!important` 중첩 주의
- inline style 과 className 혼용 — 새 컴포넌트 작성 시 inline `style={{}}` 로 `#E53935` 하드코딩 말고 `packages/shared` 의 `BRAND_COLORS.primary` import

### 5.3 react-d3-tree 사용 패턴 (OrganizationChart)

- vertical orientation, step path
- nodeSize 250x150, depthFactor 150, separation siblings 1.5 / nonSiblings 2
- zoom scale 0.3 ~ 3
- 커스텀 노드는 SVG `<g>` + `foreignObject` 패턴 (AntD Tag 렌더링용)
- **신규 4등급 체계 매핑은 `utils.ts` 안에 위치** — 새 컴포넌트에서 재사용 시 `import { gradeColors, gradeLabels } from '@/components/OrganizationChart'`
- `onUpdate` 콜백에서 translate/zoom 상태 sync — 이 패턴 유지 필요 (drag 중 state drift 방지)
- react-d3-tree의 `renderCustomNodeElement` prop은 매 프레임 재호출되므로 `CustomNode` 내부에서 **heavy computation 금지**

### 5.4 admin 페이지 공통 패턴

```
DashboardLayout
  └─ Content
     └─ Card (title + body)
        └─ Row gutter={16}
           └─ Col xs={24} sm={12} lg={6}
              └─ Statistic / Table / Form
```

- 상단 Title (`<Title level={2}>`) + `ApartmentOutlined`/`TeamOutlined` 등 아이콘 prefix
- Statistic 카드 4개가 한 행에 있는 패턴 반복
- Table은 pagination + rowKey + size="small" 자주 사용

### 5.5 함정 (pitfalls)

- **`#7CB342` 를 코드에 새로 추가 금지**. 페르소나 카드가 연두색으로 적혀 있어도 실제 코드는 빨간색임.
