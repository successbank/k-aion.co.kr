## 3. 발견된 이슈 (자동화 관점)

### [Critical] CR-3-01 — 검증 게이트 v2를 강제할 실행 메커니즘이 전무
- **현상**: `.claude/CLAUDE.md`의 v2 10대 원칙(증거 기반 완료, 기능 1개=1사이클, 누적 통합 검증)을 강제할 Skill·Hook·CI 전부 부재. 담당 페르소나(강민호/박준혁/윤재호/이정우)가 "수동으로 기억하여 실행해야 함" 상태.
- **영향**: 페르소나 시스템이 자기 규칙 위반을 자가 탐지 불가능. "완료" 선언 차단도 비강제. Stage 4 3-증거 체계(자동 테스트 + 수동 스크린샷 + git diff)를 돌릴 공용 도구 부재.
- **위치**: `/data/successbank/projects/kaion/.claude/skills/` 부재, `/data/successbank/projects/kaion/.claude/hooks/` 부재, `/data/successbank/projects/kaion/.claude/settings.json` 부재.

### [Critical] CR-3-02 — 테스트 커버리지 0% + e2e-spec 실행 불가
- **현상**:
  1. `apps/backend/jest.config.js`가 `rootDir: 'src'`이므로 `apps/backend/test/app.e2e-spec.ts`(유일한 e2e 파일)가 수집되지 않음
  2. `app.e2e-spec.ts`가 `supertest`를 import하지만 `apps/backend/package.json`의 devDeps에 `supertest` / `@types/supertest` **부재** → 빌드 불가 상태
  3. 활성 `.spec.ts` 0 파일 → `pnpm --filter @kaion/backend test`가 "No tests found"로 **silently 통과**
- **영향**: CI가 생겨도 false green(0 테스트 통과). 개발3팀 이정우의 `unit-test-gen` Skill 부재와 맞물려 수당 체인(5+ 모듈) 전체가 회귀 검증 무방비.
- **위치**: `/data/successbank/projects/kaion/apps/backend/jest.config.js`, `/data/successbank/projects/kaion/apps/backend/test/app.e2e-spec.ts`, `/data/successbank/projects/kaion/apps/backend/package.json` (supertest 누락)

### [Critical] CR-3-03 — `.bak` 파일 4개가 git-추적 중 / .gitignore 미등록

## 4. 보상플랜 관련 내용

### 4.1 첨부 이미지 매트릭스와의 관계 (개발3팀 관점)

개발3팀은 수당 체인을 **직접 구현하지 않는다**. 대신 **매트릭스 정합성 검증을 자동화하는 Skill**을 만드는 역할이다.

### 4.2 매트릭스 자동 검증의 재료 (이미 있는 API 활용)

| 이미지 제품 | 이미지 매트릭스 (판매원/팀장/지사장/센터/판매가) | 검증 방법 |
|-------------|-----------------------------------------------|-----------|
| 고주파(온체) | 50만 / 100만·지점120만 / 20만(소계5만) / 5만 / 330만 | **기존 `GET /v1/compensation-plan/overview` 호출 → `commissionTable[0]`과 비교** |
| 펄스온 | 40만 / 80만 / 15만 / 5만 / 249만 | 동일 — `commissionTable[1]` |
| 제트5 | 25만 / 50만 / 5만 / 5만 / 150만 | 동일 — `commissionTable[2]` |
| 통증 패치 | (빈칸) / 2만 / 4,800 / 2,400 / 4만8천 | 동일 — `commissionTable[3]` (판매원은 0) |
| 전용젤 | (빈칸) / 1만5천 / 3,000 / 1,500 / 3만 | 동일 — `commissionTable[4]` (판매원은 0) |

**★ 핵심 발견**:
- `/v1/compensation-plan/overview`는 `@Public()` 데코레이터로 **인증 없이 호출 가능** → 자동화 Skill이 curl 한 줄로 전체 commissionTable을 dump할 수 있음.
- 컨트롤러 코드(`compensation-plan.controller.ts:86-131`)의 하드코딩된 commissionTable은 **이미 이미지와 대부분 일치**하지만 1건 불일치 발견:
  - 고주파(온체): 컨트롤러 하드코딩 `salePrice: 2860000` (286만) vs 이미지 `330만`
    → **Stage 2에서 이 하드코딩값이 ProductCommissionRate 테이블 실제 값과 어느 것이 source-of-truth인지 재확인 필요**.

### 4.3 매트릭스 검증 Skill 설계 (이미 가능, 미구현)

```yaml
skill: check-compensation-matrix
purpose: 이미지 매트릭스 ↔ 코드/DB 매트릭스 자동 diff
actions:
  1. curl http://localhost:5667/api/v1/compensation-plan/overview | jq '.commissionTable'
  2. curl http://localhost:5667/api/v1/compensation-plan/commission-rates/active-summary
  3. 이미지 매트릭스를 expected JSON으로 하드코딩
  4. 3×5 행 비교 + 누락/초과 필드 리포트
  5. POST /v1/compensation-plan/bonuses/simulate를 5제품 × 4등급 × 샘플 판매자로 20회 호출
  6. 각 호출의 bonus 분배 결과를 expected와 diff
  7. 결과: pass/fail 매트릭스 + diff 상세 + 저장: prd2/stage2_matrix_diff.md
```

**→ 이 Skill은 오늘 당장 만들 수 있음**. 재료(API 엔드포인트, 이미지 데이터, 코드 base rate)가 전부 존재. 개발3팀 페르소나(장우혁/이정우)가 Stage 2.1 매트릭스 정합 검증 핵심 도구로 즉시 투입 가능.

### 4.4 nuance 3건 (이미지 vs 코드)에 대한 자동화 접근

1. **"100만/지점120만"** (온체 팀장): 현재 overview 컨트롤러에서는 `teamLeaderCommission: 1000000` 단일. 지점 차등 필드 부재 → Skill이 schema diff를 먼저 탐지하여 "이미지엔 있는 차등이 코드엔 없음" 리포트.
2. **"20만 (소계 5만)"** (온체 지사장): `branchManagerCommission: 200000`, `centerCommission: 50000` → 20만+5만(센터)을 둘 다 지급한다는 의미라면 Skill은 sum validation만 수행. 5만이 20만에 **포함**된다는 뜻이면 schema 해석 차이 리포트.
3. **통증패치/전용젤 판매원 빈칸**: 컨트롤러 하드코딩 `salespersonCommission: 0` → 이미 "미지급" 해석 반영됨. Skill은 `0과 빈칸이 동일한지` 이미지 원문 인용하여 사용자 확인 유도.

### 4.5 보상플랜 자동화 수확물 (본 팀 기여 영역)

### 5.7 함정 (Skill 작성 시 걸리는 것들)

- `apps/backend/package.json`에 `supertest` 부재 → e2e 검증 Skill이 supertest를 전제하면 실패 → 대안: `axios` or 순수 `http.request`
- `.eslintrc.js`의 `'prettier/prettier': 'warn'`은 warn이라 `eslint --max-warnings 0` 옵션 추가해야 pre-commit에서 차단 가능
- docker-compose의 backend command가 `pnpm install --frozen-lockfile || pnpm install` — lockfile 불일치 시 fallback 발생 → Skill이 lockfile drift 감지 필요
- `.gitignore:83-89`에 `**/verify-genealogy*`, `**/GENEALOGY_VERIFICATION_REPORT.md`가 등록됨 → 과거 수동 검증 스크립트가 있었으나 모두 삭제됨 (재생성 방지 목적 추측)

### 6.3 팀 간 자동화 의존 그래프 (간략)

```
  ├─→ QA팀 (테스트 생성/실행 자동화)
  ├─→ 개발1/2팀 (코드 생성/검증 Hook)
  ├─→ 시뮬레이션팀 (통합 시나리오 기동)

  └─→ 리서치팀 (PoC 검증)

개발3팀 (자동화) ←────
  ├─← PM팀 (규칙/승인/우선순위)
  ├─← 개발1/2팀 (자동화 대상 모듈 정보)
  └─← QA팀 (검증 기준값 제공)
```
