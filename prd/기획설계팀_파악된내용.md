## 5. 향후 개발 참조 사실 (기획설계팀 전용 메모)

1. **PRD 2종 모두 stale** — 신규 기능 기획 시 반드시 `schema.prisma` + `migration 20260120_grade_restructure` + `ProductCommissionRate` 실제 seed를 먼저 확인. PRD는 "의도 참고"로만 사용.

2. **등급 체계 신 체계로 통일**:
   - `SALESPERSON`: 판매원 (구 MEMBER+AGENT 통합) · `TEAM_LEADER`: 팀장 (구 MANAGER) · `BRANCH_MANAGER`: 지사장 (구 BRANCH_CHIEF+DIVISION_CHIEF 통합) · `CENTER`: 센터 · `ADMIN`: 관리자. 신규 명세·와이어프레임에서 이 용어만 사용.

3. **이중 계보는 사실상 후원계보 단일**. "추천계보 = 보너스, 후원계보 = 승급" 구조는 폐기됐음. 모든 upline 탐색/보너스 분배는 `sponsor` 기준으로 통일해야 함 (단, bonus-simulator가 `recommender`로 돌아가는 Critical 버그 존재 — C-3).

4. **수당은 제품별 매트릭스 기반**. `ProductCommissionRate(product_id, recipient_grade) → amount` 구조. 신규 제품 등록 시 **즉시 4개 등급의 수당율을 함께 등록하지 않으면 해당 제품 판매 보너스는 0원**.

5. **BonusType = 단순 라벨링 역할**. 2종(SALES_COMMISSION/EDUCATION_MANAGEMENT)은 단순히 "어느 등급이 받았나"를 분류하는 용도. 실제 금액 결정은 `ProductCommissionRate` 단독 참조. bonus-calculator L363~370 참조.
   - `SALESPERSON`/`TEAM_LEADER` → `SALES_COMMISSION`
   - `BRANCH_MANAGER`/`CENTER` → `EDUCATION_MANAGEMENT`

6. **한시적 승급 조건은 SystemConfig DB row**. 코드에서 hardcoded 된 값이 아니므로, "정상 10명" 복귀 시 `PROMOTION_TEMPORARY_CONDITION_ACTIVE = false`로 SystemConfig 수정만 하면 됨. 관리자 화면 미구현 시 수동 SQL.

7. **승급 조건의 "3팀 분산" 제약은 완전 제거됨**. 단순 `sponsorId = memberId` 카운트. 기획자가 "3팀 분산" 룰을 다시 요구하면 `promotion.service.ts`를 재작성하고 `CultivationRecord` 모델을 활용해야 함.

8. **PV는 dead data**. `Member.cumulativePv`/`agentPromotedAt` 필드는 남아있으나 승급에 영향 없음. 제품 판매 시 PV 누적은 여전히 일어나나(확인 필요), 읽는 쪽이 없음. 신규 기획에서 PV를 요구 조건으로 제시하면 재설계 필요.

9. **functions 함정**:
   - `.bak` 파일 4개 (bonus-calculator.service.ts.bak 등)는 구 체계 기반 — 부활 금지 (강민호 승인 필수)
   - `prisma/seed.ts` / `prisma/seed-commission-rates.ts`는 빌드 실패 상태 — 신규 seed 작성 필요
   - `genealogy-raw-queries.ts` raw SQL은 성능 핫스팟 — 리팩터 금지
   - `members/README.md`의 API 14개 주장과 5단계 enum은 stale — 참조 금지

10. **RecognizedSales / RecognitionType 모델의 운영 상태 불명**. schema에 완전히 살아있으나 신 체계와 어떻게 상호작용하는지 기획 문서 없음. Stage 2에서 박준혁 PM에게 확인 요청 필요 (폐기 vs 보존).

11. **RBAC 미완**: 대부분 members.controller 엔드포인트에 `@UseGuards(JwtAuthGuard, RolesGuard) + @Roles(ADMIN)`이 적용됐으나, `product-commission-rates.controller.ts`는 가드 미적용. 수당율 수정이 무권한 호출 가능한 상태일 수 있음 — 보안 이슈.

12. **temp_members → members migration**: 신규 가입은 `TempMember`에 먼저 저장되고 추후 정식 전환되는 것으로 추정. 정확한 flow는 `temp-members` 모듈 확인 필요 (본 분석 범위 외).
