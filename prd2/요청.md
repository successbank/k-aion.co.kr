### 항목 6: Simulator vs Calculator upline mismatch 처리 방향

**상황** (개발2팀 C1, 시뮬 C4, 기획설계 C-3 발견):

**자율 결정**: **Simulator를 Calculator에 맞춤** ('recommender' → 'sponsor')

**이유**:
- 실제 운영 코드(Calculator)가 source of truth

- Simulator는 검증 도구일 뿐, 실제 데이터 영향 없음
- 1줄 변경 (`'recommender'` → `'sponsor'`)
- 추가 검증: 변경 후 시뮬과 실제가 일치하는지 확인

**영향 파일** (Stage 2.7):

### 항목 20: MON-004 `/health` 런타임 실패 발견 — bind mount inode 끊김 원인

**상황**: Phase A 런타임 검증 중 `curl http://localhost:5667/health`가 404 반환. 체크리스트 MON-004는 PASS 마킹 상태였음. 탐색 결과:
- 호스트 `docker/nginx/nginx.conf`는 `proxy_pass http://backend/api/health;` (신 버전, 정답)
- 컨테이너 `/etc/nginx/nginx.conf`는 `proxy_pass http://backend/health;` (구 버전)
- `docker-compose.yml`은 bind mount 설정 정상 (`./docker/nginx/nginx.conf:/etc/nginx/nginx.conf:ro`)

**원인**: 호스트 파일 수정 시 atomic-replace(vim 등)로 inode가 바뀌었고, 컨테이너는 기존 inode를 계속 참조해 **구버전을 보게 됨**. `nginx -s reload`만으로는 해결 불가 — 파일 내용 자체가 컨테이너 관점에서 old.

**자율 조치**: `docker-compose restart nginx` 실행 → 컨테이너가 현재 호스트 파일을 재-mount → `/health` 200 정상.

**결정**: MON-004 PASS 유지. 단 **체크리스트 v2 검증 게이트 원칙에 따라 "정적 검증 리스크"가 실제 현실화된 사례로 기록**하며, 차후 MON-004 항목에 "호스트 파일 교체 후 nginx restart 필수" 주석 추가 권장.

**시각**: 2026-04-16

**파급**: Stage 4 런타임 검증 중 "정적 증거만으로 PASS 마킹한 다른 항목도 nginx/backend restart 후 재확인 필요" — 특히 설정 파일 수정이 관여된 항목(MON-002 access_log, DEV3-004 settings.json 등).
