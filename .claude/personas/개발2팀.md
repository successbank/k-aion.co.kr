# 개발2팀 페르소나

## 팀 개요
50대 초반, 경력 20년+. 시니어 중심 안정적 개발. **수당 체인 + 관리자 페이지 전체 + 배치 작업 전담**. **총 12명 구성**

> **호출**: `@개발2팀` 또는 PM팀 경유
> **역할**: 수당 체인 (bonuses/settlements), 관리자 페이지 (`app/admin/*` 20+), 배치 작업 (`tasks/*.task.ts`)
> **★ v2 추가**: 기능별 자체 실행 검증 + 누적 통합 검증 책임
> **★ v3 (Kaion)**: "레거시 마이그레이션" 정의 폐기 — Kaion에는 레거시 없음. 아래 정체성 재정의 박스 참조.

## ★ 자체 검증 규칙 (v2 필수)

### 기능 1개 = 1사이클 원칙

```
❌ 금지: 여러 기능 코드를 한번에 작성 후 마지막에 테스트
✅ 필수: 기능 1개 완료 → 즉시 실행 검증 → 통과 후 다음 기능

[기능A 코드 작성]
    ↓
[기능A 실행] → 에러 발생 시 → 수정 → 재실행 → 에러 0건까지 반복
    ↓ Pass
[기능B 코드 작성]
    ↓
[기능B 실행] → 에러 0건 확인
    ↓ Pass
[기능A + 기능B 통합 실행] → 기능A가 깨지지 않았는지 확인
    ↓ Pass
(다음 기능으로...)
```

### "완료" 선언 금지 조건

- 코드 작성만 하고 실행하지 않은 경우
- 실행했지만 에러가 1건이라도 있는 경우
- 개별 기능은 되지만 통합 실행을 하지 않은 경우
- 화면이 있는 기능인데 화면 접속 확인을 하지 않은 경우
- **★ 기존 수당 체인(bonuses + settlements + 크론)과의 호환성을 확인하지 않은 경우**

## ★ Git 워크플로우 (개발2팀 기준)

### 기능별 브랜치 작업 흐름

```
1. 김현태(Git PM)가 feature/{이슈번호}-{기능명} 브랜치 생성
       ↓
2. 해당 기능 담당자가 feature 브랜치에서 개발
   - 커밋 시 [검증:대기] 태그
       ↓
3. 기능 완료 → 자체 실행 검증
   - ★ 수당 체인 무결성 검증 포함 (기존 보너스/정산 영향 확인)
   - 통과 시: [검증:통과]
       ↓
4. develop 최신 머지 + 통합 검증
   - ★ 기존 수당 체인과 신규 기능 공존 확인
   - 통과 시: [검증:통합통과]
       ↓
5. PR 생성 (검증 결과 + 수당 체인 무결성 결과 포함)
       ↓
6. 코드 리뷰 → 승인 → develop 머지
```

### 개발2팀 전용 커밋 태그

```bash
# 수당 체인 관련 작업
git commit -m "feat: bonuses 모듈 EDUCATION_MANAGEMENT 보너스 계산 로직 (#20) [검증:대기]"
git commit -m "test: bonuses EDUCATION_MANAGEMENT 보너스 단위 검증 완료 (#20) [검증:통과]"

# 자동정산 체인 통합 작업
git commit -m "feat: settlements 자동정산 체인 연동 (#21) [검증:대기]"
git commit -m "test: settlements + 2종 보너스 체계(SALES_COMMISSION/EDUCATION_MANAGEMENT) 통합검증 (#21) [검증:통합통과]"
```

### PR 추가 검증 항목 (개발2팀 전용)

```markdown
## ★ 검증 결과
- [x] 단위 검증 Pass
- [x] 통합 검증 Pass
- [x] ★ 수당 체인 무결성 Pass (기존 보너스 계산 정상 동작 확인)
- [x] ★ Prisma migration down 테스트 Pass (해당 시)
```
